# 63 — P0:行横划判据用局部坐标,长拖中途误认领吃掉手势,「滑不动」真根因

**Status:** resolved(已修复;真机同脚本复验通过,用户实操确认 2026-09-01)

**Severity:** P0(全部列表屏的每一行都挂着这个判据;票 62 修完用户仍复报,本票才是主犯)

## 现象(用户真机复报,2026-09-01)

单次按压不抬起:手指按住持续上滑,滑过一定距离后**上滑下滑都失效**,期间手指
一直在屏幕上;抬手重按又能滑一段,再死。与票 62 建模的「多把手势 + 回勾」是两回事
——所以方向门治不了。

## 复现(确定性脚本,真机 25113PN0EC,8-31 含票62修复的包)

关键变量是**横向漂移**——拇指长拖天然带弧线,而此前所有注入手势 x 恒定,永远测不到:

```bash
# G4(复现):带 3px/发 横向漂移的弧线拖
input motionevent DOWN 610 2200
# 上行 46 发:y 2170→800 步长 30,x 每发 +3(共漂 138px)
# 回拖 12 发:y 860→1580 步长 60(仍按住)
# UP
```

录屏(指针叠加层开)YDIF 逐帧:

| 手势 | 表现 |
|---|---|
| G1 对照:同参数、x 恒定 610 | 上行/回拖**全程跟手** |
| G4:+3px/发 漂移 | 跟手约 15 发(dx 累积 ≈45px 越过 slop)后**冻结**,余下 31 发上行 + 整段回拖零响应,抬手才恢复 |

关键帧:指针从 Y:1270 → 800 → 回拖 1100(Prs=1.0 全程按住),列表内容像素级不动。

## 定位

`ui/common/RowTap.kt` 的 `cancelTapOnHorizontalDrag`(票 23,挂在 8 个列表屏的每一行):

1. 它挂在**行**上,`change.position` 是行内**局部坐标**。列表跟手滚动时,行随手指
   一起移动 —— 手指在行自己的坐标系里根本没动,**局部 dy 恒 ≈ 0**(只剩一发事件的
   跟踪滞后);列表不横滚,局部 dx 却是真实的横向漂移,单调累积。
2. 于是长拖中途漂移一过 touch slop(density 520 上 ≈26px),
   `abs(dx) > slopPx && abs(dx) > abs(dy)` 必然成立 → 误认领,
   `change.consume()` 消费**之后每一发** → 纵向滚动的拖拽(Main pass)看到事件
   已被消费,当场取消 → 抬手前列表对这根手指彻底失聪。
3. 原有的护栏「认领前 `change.isConsumed` 就 break」形同虚设:它跑在 **Initial**
   pass,而滚动在 **Main** pass 消费;每发新事件到 Initial 时消费位都是干净的,
   「上一发已被滚动吃掉」在 Initial 永远看不见。

为什么此前查不到:测试注入(`input swipe` / 恒定 x 的 motionevent)没有横向漂移,
局部 dx 恒 0,判据永不触发;真手指必带弧线。也解释了「滑过一定距离才死」
(漂移要累积过 slop)和随机感(直的那几把不死)。

排除项:material3 `pullToRefresh` 节点 `enabled=false` 只会返回 `Offset.Zero`
不吃手势(1.4.0 源码对过);抽屉 `DrawerHost` 同款判据挂在不随滚动移动的固定容器上,
无此病。

## 修复

`RowTap.kt`:认领决策挪到同一发事件的 **Final pass**(`awaitPointerEvent(Initial)`
之后再 `awaitPointerEvent(Final)` 拿同一发的落定状态):

- 新增纯函数 `rowTapStep(consumedByOthers, dx, dy, slopPx)`:**消费检查在前**——
  滚动(在 Main)消费过任何一发就 `YIELD`,这一把手势从此让位(横划取消点击的活,
  滚动的消费本身已经干了);没人消费才轮到 `shouldCancelRowTap` 判 `CLAIM`。
- 认领后的消费仍在 Initial(要抢在内层 `clickable` 之前),并且**连抬手那一发也消费**
  ——认领发生在倒数第二发时,clickable 还没见过被消费的事件,放过 up 会算成一次点击。
- `shouldCancelRowTap` 本体与票 23 的单测不动。

## 单测

`RowTapTest` 新增 3 例:滚动消费过必 YIELD(哪怕局部坐标看着像横划)、
无人消费时 CLAIM/WATCH 归位、G4 真机事件序列回放(46 发,dx 累到 138px)全程不认领。
