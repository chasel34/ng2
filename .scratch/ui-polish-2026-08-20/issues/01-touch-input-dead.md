# app 窗口偶发「触摸完全失灵」，force-stop 才能恢复

Status: open（2026-08-20 记录，本轮不处理）

## 现象

app 运行一段时间后进入一种状态：画面仍在正常渲染（截图正常、动画照跑），
但**该 app 窗口完全不响应触摸**：

- `input swipe` 滑不动列表（内容位置纹丝不动）；
- `input tap` 点顶栏返回按钮无效；
- `input keyevent 4`（返回键）无效，退不出当前屏。

同时 **系统层输入是好的**：`input keyevent 3`（HOME）能正常回桌面
（`mCurrentFocus` 切到 NexusLauncher）。所以不是 adb 通道或模拟器输入坏了，
是 app 窗口这一层不吃事件。

`adb logcat` 里**没有** ReactNative 异常、没有 ANR、没有 FATAL。

`am force-stop com.chasel.ng2.dev` 后重启即恢复正常，触摸一切如常。

## 复现

尚无确定性复现步骤。2026-08-20 一轮 UI 验收中**两次独立撞见**：

1. 验收 subagent 连续驱动模拟器约 40 分钟后（帖子详情页）；
2. 主会话接手后不久，同样在帖子详情页。

两次都是在帖子详情页（`src/app/topic/[tid].tsx`）撞上的，但不能据此认定只在该屏发生
——那一轮的操作本来就绝大多数落在详情页。

## 排查线索

- 与本轮 7 项 UI 改动**大概率无关**：改动前的会话里也出现过类似「点不动」的迹象，
  且首页/详情页都中招过。需要在干净的 HEAD 上对照复现一次才能定论。
- 症状与既有经验里那条「Android 触摸分发被父边界裁剪」高度相似
  （子 view 布局在父边界外、靠 transform 拉回 → 画面对但热区不对）。但那条的典型表现是
  「点击好使、原生滚动全灭」，本条是**点击也一起死**，不完全吻合。
- 值得先查的方向：某个全屏透明遮罩（`OverflowMenu` 的 `StyleSheet.absoluteFill`
  关闭层、FAB 展开层、对话框层）在关闭后没卸载干净，留下一层吃掉所有事件的透明 View。
  但如果是这种，第一次 tap 应该会把它关掉 —— 实测连点多次仍无效，与该假设矛盾，
  需要用 `adb shell dumpsys window` / view hierarchy 实证，别停在猜测。

## 影响

自动化验收会被卡死且**容易误判成功能 bug**（本轮就险些把「浮层点不动」记到浮层头上）。
真机上如果同样存在，用户视角就是「app 假死，必须杀进程」，属 P1 级体验问题。

## 下一步

1. 在干净 HEAD 上尝试复现，确认是否为本轮改动引入（大概率不是）。
2. 复现时抓 `dumpsys window`、`dumpsys input`、view hierarchy，看焦点窗口和触摸区域归属。
3. 若能稳定复现，二分定位到具体屏/具体交互。
