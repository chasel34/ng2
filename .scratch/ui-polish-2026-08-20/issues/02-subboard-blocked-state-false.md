# 子版块「已屏蔽」状态疑似误报（attributes 魔法数白名单不全）

Status: open（2026-08-20 记录，本轮不处理）

## 现象

「子版块 · 网事杂谈」管理页里，`网络游戏综合` 显示为 **已屏蔽**，
但用户从未屏蔽过它 —— 而且它照常出现在帖子列表页顶部的子版块 chip 行第一位。

用户最初的怀疑是「chip 行漏了过滤」或「fid 映射错位」，核下来都不是（见下）。

## 已排除的两件事

1. **chip 行没有漏过滤，也不该过滤。** chip 行（`src/app/board/[id].tsx`）和管理页
   （`src/app/board/sub-boards.tsx`）读的是**同一份数据** `data.pages[0].subBoards`，
   中间没有任何过滤。NGA 的「屏蔽」语义是让服务端在帖子列表里不返回该子版块的帖子，
   **不是隐藏入口**，所以已屏蔽的子版块仍出现在 chip 行是设计如此。
   （要不要改成「屏蔽后 chip 也隐藏」是独立的产品决定，不在本条范围。）
2. **fid 映射没有错位。** 2026-08-20 验收逐个点 chip 核对过标题，全部一致，
   还验了一层嵌套（网络游戏综合 → 上古卷轴Online ✓）。
   同轮修掉的 chip React key 撞车（`board.id` → `${board.kind}/${board.id}`，
   合集 stid 与版块 fid 编号空间重叠）是**另一个独立 bug**，治的是「点进去跑错版块」，
   不解释状态显示错。

## 真正的疑点

状态判定是一张**六个魔法数的白名单**（`src/core/api/sub-board.ts`）：

```ts
export const SUBSCRIBED_ATTRIBUTES: readonly number[] = [7, 558, 542, 2606, 2590, 4654]
subscribed: SUBSCRIBED_ATTRIBUTES.includes(attributes)
```

凡是 `attributes` 不在名单里的，一律落到 `subscribed: false`，UI 就显示「已屏蔽」——
**没有「未知」这一档**。文件顶部注释自述这行的出处是 MNGA 源码里那句
"how can I fucking know this ??"，并写明「随时可能随 NGA 更新失效，
失效的表现是状态显示反了/按钮不可点」。

所以 `网络游戏综合 = 已屏蔽` 极可能是**白名单漏了一个取值造成的误报**，
它压根没被屏蔽 —— 这也正好解释了为什么它照常出现在 chip 行里。

## 下一步

1. 带登录态打一次 `topic-list` 接口，抓 `网络游戏综合` 的真实 `attributes` 值，
   对着白名单看差在哪。（本项目有教训：结论要用 curl 对拍实证，别归因给「服务端拦截」。）
2. 多抓几个已知「确实订阅了 / 确实屏蔽了 / 没动过」的子版块做样本，
   看 `attributes` 是不是位标志（bitmask）而不是枚举 —— 若是，白名单就该换成按位判断，
   这类「六个不连续魔法数」的形状本身就很像有人把 bitmask 的若干组合硬记了下来。
3. 在判据修好之前，考虑给 UI 加「未知」态，别把认不出来的一律画成「已屏蔽」误导用户。

## 影响

用户会以为自己屏蔽过某个子版块（或反过来以为订阅生效了），
而实际服务端状态与显示不符。不影响其它功能。
