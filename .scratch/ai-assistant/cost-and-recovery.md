# AI 开销控制与异常处理

用户明确强调开销控制及异常处理的重要性，并已确认单次共享额度、用量透明、分类重试、保留成果与手动继续等产品原则。本文件细化 [已确认需求](spec.md) 与 [技术方案](technical-design.md)；技术细节仍需验证，金额、次数或时间阈值及具体界面尚未定稿。

Agent 继续自主选择工具和 skills。预算、取消、错误分类与持久化由 harness 执行；skill 可以指导如何利用有限资料回答，不能自行提高额度、解除访问限制或重启用户停止的任务。

## 用户可理解的开销控制

建议提供“单次分析额度”，另提供可选的“每日额度”。首次概览和每次用户追问都是一次分析，其中所有模型调用、整理摘要、自动修复、重试与最后回答合并计算，不能每次调用工具就重新获得一份额度。每日额度只统计本机此 App 发起的请求，不能代表同一个 Key 在其他设备或产品中的消费。

默认概览保持简短；个人分析仍尽可能覆盖已确认的最多 300 条文本样本。初始图片总计最多一张，后续读图按问题及剩余额度决定。若无法在额度内处理完整样本，展示实际处理数量与未处理范围，允许继续，不能自动降低采样目标并声称完成。

设置中的具体金额和默认 token 上限先通过代表性样本确定；不直接把服务商最大上下文或默认输出上限用作 App 的额度。界面优先展示本次预计费用和剩余额度，展开后显示 token、模型请求、图片和重试用量。费用标为估算，采用服务商计价币种；没有可靠汇率时不换算成人民币。已核实 DeepSeek 峰时为 UTC 01–04 与 06–10 工作日，对应北京时间 9–12 点与 14–18 点，正是国内主要使用时段；默认估算按峰时价，只有确定处于谷时才用半价。

到达额度时保留已有结果，显示“已达到本次额度”与“继续分析”。继续意味着新增一段明确额度，仍累计进原对话和当天总量；不能静默无限续额。达到每日额度时，普通“继续”不能绕过它，需要用户修改额度。已有资料优先复用。

多对话可以存在并等待执行；同一会话只运行一个任务，跨会话统一限制模型、论坛、搜索、图片并发。重复点击不重复创建同一次请求，排队等待本身不调用模型。

## 发送前控制与用量记账

DeepSeek 当前区分缓存命中输入、未命中输入和输出价格，并存在时段价格；价格也可能调整。金额控制需要价格版本与核实日期，不能只用总 token 乘单一价格。[官方定价](https://api-docs.deepseek.com/quick_start/pricing/)。

每次模型请求发送前，检查并预留该请求的输入估算、输出上限和允许的重试开销。输入包括工具定义、已加载 skill、资料、图片和协议要求回传的历史字段。未知缓存命中按未命中估算，时段不确定时采用适用价格中的较高值。多个任务的预留必须原子更新，不能分别读到相同剩余额度后同时超支。

每次请求显式设置输出上限和思考配置；思考与工具调用相关生成也属于开销。服务商返回的 completion 总量与其中的 reasoning 明细不能重复相加。收到 usage 后更新该次请求的记录，价格版本随记录保留，不因价格表升级重算旧记录。[请求参数与 usage](https://api-docs.deepseek.com/api/create-chat-completion/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

运行记录分别保存：

- 已收到服务商 usage 的用量，以及按对应价格表计算的费用估算。
- 已发出、仍执行中的请求预留。
- 已发送但结果或 usage 不完整的请求，标记为待核实并保留保守预留，不能按零消耗处理。

应用重启保留上述状态，跨日运行也保留原请求的归属与预留，不能用重启或午夜重置清掉未结用量。会话历史删除不应顺带重置当日用量；用量记录与正文生命周期分开。

DeepSeek 的完整流式 usage 位于最终结束块；连接中断可能使客户端收不到它。因此本机金额额度是保守的请求控制与估算，不能承诺服务商账单绝不超出到分的金额。取消已发出的请求也不能等同于撤销收费。价格过期或估算不可靠时明确降低费用信息的可信度，仍保留 token、请求数与输出等上限。[流式协议](https://api-docs.deepseek.com/api/create-chat-completion/)。

## 避免任务持续消耗而没有进展

- 按来源版本复用相同页面、图片与工具结果；用户询问新进展时可显式刷新。复用结果能减少读取与处理，但重新把内容送进模型仍计入输入用量。
- 反复读取相同资料、反复发出无效参数、重复得到相同失败时向 agent 返回进展状态；持续没有新增证据且达到限制则结束本次调查，保留结论与局限。
- 工具返回分页、有界正文与未读索引，避免一次返回整座长楼或把大量图片自动转成模型输入。
- 按完整消息轮次提前整理上下文；整理请求本身也收费，记录资料版本与整理结果，避免每轮重新总结全部历史。整理失败时保留原工作上下文，不覆盖为不完整摘要。
- 除本次费用与 token 外，分别限制模型尝试次数、工具执行、连续失败、总耗时、单请求等待、下载量和图片解码资源。心跳或空白响应不能无限延长总时限。
- 接近额度时预留一次有限的收尾输出，让 agent 有机会整理已得结论；若已无额度、模型不可用或用户已停止，由 App 直接展示现有草稿、来源与未完成原因，不额外付费生成错误说明。

## 异常分类与恢复行为

模型错误需要按实际状态码和响应含义分类。DeepSeek 将认证、余额、参数、限流与服务异常分别定义；不能用“请求失败”统一触发重试。[官方错误说明](https://api-docs.deepseek.com/quick_start/error_codes/)。

| 情况 | 建议行为 | 界面与恢复 |
| --- | --- | --- |
| 未配置 Key、Key 无效、余额不足 | 当前模型任务停止，不自动重试，不自动换服务商 | 指向模型设置或余额问题；修正后在原对话继续 |
| 请求格式、参数或模型能力不兼容 | 不原样重试；区分配置错误与应用适配错误 | 给出具体原因，保留输入和已有资料；不能通过静默移除图片来假装完成 |
| 明确的限流或可重试服务错误，尚未开始输出 | 在共享次数和时间预算内退避重试；有 Retry-After 时遵守，超出等待额度则暂停 | 显示等待及重试进度，支持停止；不能假定所有错误请求都免费 |
| 可以确认尚未发送的连接失败 | 可在限额内重试；确认为离线时等待用户恢复网络 | 不循环消耗模型调用；恢复网络不会自行重启已结束任务 |
| 已发送但未收到响应，执行结果不明 | 默认不自动重放；保留待核实用量 | 说明请求状态不确定，用户可选择重试；未看到文字不代表服务端未执行 |
| 已输出思考、文字或工具参数后断线 | 保存部分内容，标记中断，不自动重跑本次模型请求 | “继续”复用资料并从最近协议完整的位置发起新请求，可能产生新增费用 |
| 生成因长度上限结束，或工具参数只生成一半 | 标记未完成；不执行不完整调用，不自动无限接写 | 保留可见文本，提供继续 |
| 服务商内容限制或正常拒绝 | 不通过改写、换模型或自动重试绕过 | 展示可用回答或限制原因 |
| 搜索验证页、网页无法读取 | 工具返回失败类别；搜索结果摘要与已读正文分别标识 | 有足够论坛资料时继续有限回答，说明外部核查缺失 |
| 某页、某楼无权限、已删除或暂时失败 | 复用 NGA 既有 READ 恢复链，记录实际失败与缓存来源，不在外层重跑整条链 | 可继续处理独立资料；主楼等关键资料缺失时明确无法完整分析 |
| 图片下载、格式或大小不满足要求 | 有界缩放或重试，仍失败则返回未读取状态 | 保留文字与图片索引，不能声称看过该图；个人分析始终不读取图片 |
| 工具名或参数无效 | 执行前拒绝，向模型返回结构化错误，可在现有预算内纠正 | 相同错误持续出现时结束，避免“修复—重试”无限循环 |
| 上下文过长 | 提前整理；服务端仍拒绝时仅在确定可修正且有预算时重建较小请求 | 保留原始资料和覆盖信息，整理失败不能丢聊天或谎报全部已读 |
| 重复读取、连续失败或预算耗尽 | 结束当前执行，不再调新工具；有预留时有限收尾 | 区分“已完成”和“达到限制”，展示已做与未做事项 |
| 用户停止 | 取消请求、工具和退避等待；丢弃迟到的状态覆盖，不再收尾或自动重试 | 保留已保存草稿，明确已停止 |
| 应用进程被结束 | 下次启动把旧运行恢复为中断状态 | 打开历史只展示记录，由用户决定继续，不自动发起付费调用 |
| 数据库或存储写入失败 | 在继续发起付费工作前停止，不能显示保存成功 | 保留能保住的内存草稿并标记未保存；不能承诺进程结束后仍可恢复 |

局部工具失败不必终止所有分析，但是否仍有足够证据由 agent 判断；工具层提供准确状态，回答只能覆盖成功读取和实际处理的范围。跨多个工具的同一批调用中，成功项各自保存，失败项显式返回，恢复时不丢弃成功项。

### 重试的实现边界

模型层自动重试只用 Koog 1.2.0 的 RetryingLLMClient 及其 RetryConfig。它在收到首个 frame 后不重试，也会传播取消；其重试判断依赖异常文本，不足以区分“未发送”与“已发送但结果未知”。App 不另写重试逻辑：在客户端之外按 EventHandler 事件记录每次尝试、usage 与预留，费用预算在发送前检查；配置无法表达的分类需求向上游反馈。[重试源码](https://github.com/JetBrains/koog/blob/1.2.0/prompt/prompt-executor/prompt-executor-clients/src/commonMain/kotlin/ai/koog/prompt/executor/clients/retry/RetryingLLMClient.kt)。

模型 HTTP 层、SDK 层和外层 agent 不能各自独立自动重试，导致尝试次数相乘。每次实际发出的请求都有独立尝试记录，继承本次分析的总限额。NGA READ 链继续按 [ADR-0002](../../docs/adr/0002-anti-block-chain-first-class.md) 工作；其内部尝试受整体取消与时间控制，不额外再包一层完整链重试。

自动重试与用户主动继续分开：前者只恢复允许重试的当前请求；后者创建新的执行记录，复用已完成资料，不重复添加原问题。已保存的部分回答保留为未完成版本，不能直接拼接新回答并暗示内容从未中断。App 去重只能避免本机重复派发，不等于服务商保证幂等收费。

## 界面反馈

常规状态沿用“读取内容、搜索资料、生成回答”，补充“等待执行、等待重试、达到额度、已停止、已中断”。失败信息出现在对应对话中，不只用短暂 Toast；状态卡包含原因、已保留的成果和适用操作，不原样暴露堆栈、Key 或正文日志。

建议示例：

> 已达到本次额度。已整理 86 条发言，还有 124 条已读取但未分析。已有结果已保存。
> 操作：继续分析 · 查看用量

> 回答生成中断，已保留文字和 12 条来源。本次用量统计不完整，继续可能产生新的费用。
> 操作：继续 · 查看已有资料

> 外部搜索暂时不可用。本次回答仅依据论坛中已读取的内容，外部事实核查尚未完成。

这些是状态卡示意，不是固定分析流程；数字仅为示例。用户停止、数据库失败等状态卡由 App 渲染，无须模型生成。

## 验证与待定项

实现时重点覆盖：并发预留不会重复花同一份额度；usage 重放不重复记账；断线未结用量和跨日预留不因重启丢失；所有摘要及重试计入额度；停止后不会被迟到响应重新启动；已成功工具结果在恢复时不重复读取；截断工具不执行；搜索失败不当成零结果；存储失败不虚报保存；300 条范围与已处理数量保持一致。

真实样本验证后再定：默认单次额度、每日额度默认是否启用、模型输出与思考上限、全局并发、自动重试次数与时限、连续无进展阈值。使用当前 DeepSeek 的正常主题、多图楼、长回复链和长篇个人历史分别测量费用与完成质量，不能只用短对话决定默认值。金额预留的误差、未结用量的核对和价格表更新交互仍需在设置方案中细化。

实际预算、用量和恢复行为见下方实现记录；真实请求未收到可用 usage，不能将离线通过视为费用或质量已校准。

## 预算实现与当前取值（2026-09-14）

价格版本 `deepseek-flash-2026-09-14`，核实日期 2026-09-14，币种 USD。依据 [DeepSeek 官方定价](https://api-docs.deepseek.com/quick_start/pricing/)，每百万 token 的峰时价格为缓存命中输入 US$0.006、未命中输入 US$0.30、输出 US$1.20，谷时为一半。UTC 工作日 01–04、06–10 为峰时，对应北京时间 09–12、14–18。应用目前统一采用峰时保守估算；核心价格规则也覆盖确定谷时的计算。每个请求保存当时价格，旧账不随价格更新重算。完整 SSE usage 的缓存字段在 Koog HTTP 适配中保留，completion 已含思考，不重复加 reasoning。

暂定单次额度：短问答 US$0.02、默认 US$0.05、长楼与个人分析 US$0.10、更高 US$0.20。每日额度默认关闭；启用后按用户设置生效。以上金额均未完成真实样本校准，界面明确标注。每次模型输出最多 4096 token，最多两次尝试，Koog 总循环上限维持 8；跨会话一次执行一个任务。Retry-After 超过 10 秒则暂停自动重试，等待用户继续。HTTP 调用最长 90 秒，底层透明重试和重定向关闭。

输入按文本、协议字段、工具及技能定义的 UTF-8 字节数保守估算，另保留 4096 token 协议余量；图片每张预估 65536 token，不把 base64 字节数误计为文本。每次尝试都先原子预留输入及输出上限；重试继承同一分析和每日额度，下一次尝试不能先发送再补记。金额取整到微美元。较大的图片预留及暂定输出限制可能使短问答档无法直接开始多图分析，用户须显式追加额度；不会悄悄丢弃图片。

Room 3→4 自动迁移添加独立 `ai_budget` 账本，以事务读取、校验和写入预留。账本不设会话外键，删除或清空对话不会删除用量。重启把未结请求标成待核实，保留预留与原北京时间日期，跨日未结仍占用每日可用额度。旧 `ai_usage` 占位记录按原请求独立导入，缺失 usage 时用 100 万输入和 4096 输出的保守预留，明确待核实，不按零费用处理。

达到工具执行次数或连续重复读取阈值时，本次运行不再执行工具，未执行的调用按上限结果回传，并在同一次运行内用剩余预算做一次收尾输出；只有收尾之后仍然没有完整回答才报「达到限制」。同一坐标读取失败后本次运行不再重复请求，用户点继续时可以重新尝试。

确认追加额度前先保存已有结果；追加和“到此为止”都必须单选后点确定，关闭卡片只折叠为待确认。追加延续同一 analysisId，另建运行恢复检查点；每日额度仍在发送前检查。暂停额度、服务失败、用户停止和进程中断分别记录，不把正常预算暂停说成进程被系统结束。付费工作开始前存储失败会停止，界面保留未保存标记。

模型自动重试仅由 Koog RetryingLLMClient 执行。只允许 HTTP 层确认的 429/500/503 且尚未输出的请求重试一次，Retry-After 在允许等待范围内交给 Koog 配置。认证、余额、参数错误与未知结果不重放。Koog 对 `IncompleteStreamException` 的无条件重试由客户端适配转换成结果不明，防止空流被误当成未发送。发送前检查及 usage 结算接在模型事件上，实际 HTTP 重试尝试通过同一运行预算回调独立预留；不另建重试循环。

真实验证：NGA 游客列表可读，选择普通主题 `47549429`、多图楼 `47344551`，另一次受控诊断选择普通主题 `47552184`。三次逻辑模型调用都未获得可用 usage，按结果不明处理，费用/token 不填零。没有获得可用于校准的长回复链样本。依用户补充授权，服务调用受阻后停止真实调用并以离线验证完成；这些金额、图片 token 预估、输出上限、次数、等待阈值均仍需真实样本校准。详细验证见 [09 实现报告](reports/09-impl.md)。

## 未发送预留与设置恢复

预留记录区分 reserved、in_flight、settled、not_sent、rejected 和 pending_verification。429 以外的 4xx 由 HTTP 层标记为服务端明确拒绝，按 rejected 释放预留并保留请求记录，界面按认证、余额或参数适配给出对应状态卡，不计入待核实。能够确认 HTTP 尚未开始的保存失败或用户取消，原子标记 not_sent 并释放预留，不计入模型请求数量；进程重启后无法确认发送状态的旧预留仍保守标记待核实，不能按未发送清空。额度确认协程与模型任务共用取消管理，停止或删除后即使额度事务已经提交，也不会恢复模型请求。每日额度、Key、余额修正后提供手动继续入口，复用原 analysisId 和检查点，发送前再次检查每日额度，设置返回本身不发起请求。
