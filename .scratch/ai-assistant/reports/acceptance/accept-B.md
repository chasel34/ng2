## 问题清单

- [P1] 所有模型请求被 DeepSeek 以 HTTP 415 拒绝，AI 回答功能整体不可用：面板永远停在「请求结果不明 / 请求已发出但没有收到完整响应」，从未出现流式文字。复现步骤：主题详情顶栏 AI、楼层下方 AI、底部快捷操作胶囊、`/` 菜单选项、失败后点「继续」、输入框追问——六个入口全部一致失败，1–2 秒内报错。期望：票 04「回答以流式 Markdown 逐步显示」、docs/ai-assistant.md「调用使用 `deepseek-flash`…开启思考」。证据：`adb logcat --pid=<app>` 共 28 条 `java.lang.IllegalStateException: 模型 HTTP 415`，抛出点 `app/src/main/kotlin/com/chasel/ng2n/data/ai/BudgetHttpClient.kt:48`。补充排查：①带图（主楼图片 1 张）与纯文本（楼层入口，已带入「无」）两种上下文都是 415，排除多模态图片消息；②模拟器与宿主机都能连通 `api.deepseek.com`，NGA 读取正常；③用假 Key 以 `application/json`、`text/plain`、缺省、重复 Content-Type、`Accept: text/event-stream` 五种组合 curl `POST /chat/completions` 一律先返回 401，说明鉴权早于媒体类型检查——本机拿到的是 415 而非 401，即 Key 有效、请求被服务端在鉴权之后按「媒体类型不受支持」拒绝。两个待查方向留给实现：自建 `BudgetHttpFactory` 走 OkHttp 发出的 `Content-Type` 实际值（Koog `OkHttpKoogHttpClient` 用 `RequestBody.contentType().toString()`，会带 `; charset=utf-8`），以及 `TopicAgentRuntime.kt:151` 把模型 id 覆写为 `deepseek-flash` 是否为服务端实际接受的取值。注：koog `prompt-executor-deepseek-client` 为 `1.2.0-beta`，`http-client-okhttp` 为 `1.2.0`。

- [P2] 楼层入口阅读范围卡「选中楼层」计数恒为 0，与「已读 2 条」自相矛盾。复现步骤：主题详情任一楼层下方点 AI → 面板全屏 → 看阅读范围卡。1 楼与 3 楼两次结果相同：`✓ 主楼正文 1 楼` / `✓ 选中楼层 0 楼` / `已读 2 条 · 屏蔽 0 条未计入`。同一卡片在主题入口用的是楼层条数语义（第 1 页 20 楼 + 当前页 19 楼 = 已读 39 条，见 `b-longtitle.png`），所以「选中楼层」应为 1 楼。期望：票 04「楼层入口的默认范围为主楼正文与选中楼层」，范围卡应如实反映已读条数。证据：dump 片段 `选中楼层 [131,480][923,543] / 0 楼 [944,480][1006,543]`。

- [P2] 415 这类确定性客户端错误被归类为「结果不明」，保守预留不释放，失败请求持续吃掉每日额度。复现步骤：重复触发上面的 415，到设置 → AI 助手看今日用量。结果：`今日用量 · ≈ US$0.1194`、`每日 US$1.0000 · 11%（含未结预留）`、`6 次请求用量待核实`，而这 6 次请求服务端均未处理、不可能计费。期望：docs/ai-assistant.md「能够确认尚未发送的失败或取消释放预留」——415 属于服务端明确拒绝、无 usage 的确定性失败，建议与「已发送但结果不明」区分，否则用户只要遇到这个 bug 就会在无任何产出的情况下被额度锁死。证据：设置页 dump 片段（上引）。
