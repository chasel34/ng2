# AI 阅读与对话助手

## 目标与阶段

为 NG2 的主题列表、主题详情、楼层、回复链和用户历史发言提供带上下文的 AI 分析与持续对话。参考 X 的 Grok 内容入口，结合论坛的分页、主楼、引用关系和历史发言结构设计。

用户已整体确认一期产品需求，并开始按实现票推进。票 01 的框架接入、离线构建与 R8 验证已完成，验证结果与依赖边界见 [ADR-0006](../../docs/adr/0006-koog-agent-runtime.md)；业务能力及真实模型联调待完成。

## 已确认的接入方向

首期使用 DeepSeek，采用 BYOK，由用户提供自己的模型 API Key；结构应支持后续增加其他模型服务商。用户已决定优先使用 Koog 的完整能力承载 harness，不自建等价机制；harness 在 Android 本机运行。这里的本机运行指上下文组织、工具执行和会话管理；首期模型推理仍调用 DeepSeek API。DeepSeek V4.1 Flash 的图片能力已确认，不将模型支持读图作为待定产品能力。

沿用用户认可的设置方向：首期面向 DeepSeek 官方服务，提供 API Key 与默认模型配置；自定义服务地址及更多模型留待后续，当前结构预留扩展。

搜索首期选择 DuckDuckGo，目标是免费、无需单独配置搜索 Key。具体可用方式与失败处理纳入技术探索，不能把搜索页面的可访问性视为稳定 API 承诺。

框架比较见 [框架研究](framework-research.md)。当前基于 Koog 的接入结论、业务适配建议与待验证事项见 [Koog 最佳实践](koog-best-practices.md)。

用户明确选择由模型自主决策的 agent，不采用固定业务 workflow。可复用的任务方法、检查步骤和输出要求通过 skills 表达，agent 按问题选择、加载并使用；读取什么、调用哪些工具以及何时继续由模型判断。首期内置 skills，用户自定义与安装仍沿用后续扩展范围。已确认的初始上下文、300 条采样、图片与访问限制仍由 App 保证。

## 已确认的阅读场景

| 入口 | 首次分析的范围 | 用户要了解什么 |
| --- | --- | --- |
| 列表概览 | 当前列表已加载的主题，保留排序和筛选，取靠前的最多 300 个 | 最近大家在讨论什么 |
| 列表单条主题 | 该主题第一页与热门回复 | 这个主题在讨论什么 |
| 主题详情 | 第一页、热门回复与打开 AI 时的当前页；当前是第一页时只取第一页 | 主题和当前页在讨论什么 |
| 单个楼层 | 主楼正文与选中的这条发言 | 这位用户说了什么，与主题有什么关系 |
| 回复链 | 主楼正文与当前回复链的全部发言 | 各方在回应什么、有什么分歧 |
| 个人分析 | 按时间从近到远读取该用户的历史主题和回复，按发言去重后合计最多 300 条；本期仅文本 | 个人倾向、反复表达的偏好与立场 |

列表概览与列表中某个主题旁的 AI 按钮是两个入口。列表中单个主题入口默认读取该主题第一页。

列表概览保留当前列表的排序与筛选条件。已加载主题超过 300 个时取当前列表靠前的 300 个，不足时按实际数量处理。

列表中已加载的数据主要是标题、作者、时间和回复数。列入概览的主题可按问题继续读取正文和楼层。

主题详情的第一页尚未加载时需补齐。单个楼层和回复链使用主楼本身，不默认加入第一页其他无关楼层。

个人分析按时间从近到远读取，按独立发言去重。300 条是主题和回复合计，不能分别各取 300 条。不足 300 条时使用实际可访问内容；无需用户先手动加载这些历史。

## 上下文与联网

用户明确要求：用户在当前主题能够看到的内容，都应能成为 AI 直接使用或按需读取、引用的上下文。当前入口决定首次关注范围，不构成后续对话的读取上限。

可访问范围包括正常翻页、展开引用或折叠内容、查看图片等操作后可见的相关内容，不局限于当前屏幕或已加载楼层。内容包括正文、作者与时间等信息、引用关系、热门回复、贴条和图片。主题相关对话的正文图片已确认需要纳入上下文；个人分析本期例外，仅支持文本。视频和其他非图片附件本期保留链接及相关文字说明，直接读取内容留待后续。

用户已允许联网。AI 可按需搜索站外资料，并区分论坛发言与外部证据。

回答应说明实际阅读范围，并提供能返回对应楼层、主题或外部来源的引用。资料缺失、读取失败或证据不足应明确说明。只读了部分内容时不得表述成完整主题或完整历史的结论。

从一个楼层开始的对话可以按问题继续读取回复链、其他页或相关主题，不要求用户重新开对话或手动复制材料。

### 图片读取

用户已确认主题相关对话需要把正文图片加载到上下文。主题分析可能遇到大量图片，尤其是分享图楼，因此默认带入的图片需要限制；多图时默认只取一张，避免初次分析带入全部图片。

用户已确认：主题分析的首次概览总共最多带入一张图片。这个数量按整次首次概览计算，不按楼层分别计算。

主题分析默认优先选主楼第一张图片；主楼无图时取当前页第一张。单个楼层或回复链首次分析同样最多一张，从选中的发言或回复链内选取。

这个数量限制只针对默认带入。用户明确允许主题相关对话中的 agent 在需要时继续读取更多图片，无需用户逐张提供。未默认带入的图片仍应保留与所属发言的关联，使 agent 能定位、选择并读取。

图片选择和后续读取应服务于当前问题；不应仅因主题中存在大量图片就自动全部读取。AI 读图不受「仅 Wi-Fi 加载图片」设置限制，开销由预算控制。单个楼层和回复链的默认单张限制同样不影响 agent 按需继续读图。

个人分析本期只支持文本，默认上下文与 agent 后续读取均不包含图片。这个范围取代此前提出的个人分析单图限制。

### 视频与其他附件

本期保留视频和其他非图片附件的链接及相关文字说明，AI 可引用这些信息。直接读取、解析视频和非图片附件内容留待后续，不能将链接或文字说明表述为已读取附件本身。

## 首次概览与快捷操作

首次从内容入口发起分析时自动生成简短概览，下方提供输入框和快捷操作。点击快捷操作后在当前对话中继续讨论。

第一期只提供内置快捷 prompt。用户自定义新增和编辑留待后续，同时将扩展能力列为一期要求，后续快捷操作可以复用上下文读取、聊天和历史记录能力。

以下为已讨论的首批清单；具体名称、顺序和完整 prompt 文本尚未定稿：

| 入口 | 内置快捷操作 |
| --- | --- |
| 列表概览 | 深入某个话题、梳理讨论分歧、补充背景 |
| 主题详情 | 事实核查、批判性思考、梳理分歧、补充背景 |
| 单个楼层 | 事实核查、批判性思考、查找前情 |
| 回复链 | 梳理分歧、检查各方论证、事实核查 |
| 个人分析 | 查看倾向依据、查找相反表述、查看观点变化 |

事实核查应提取可核查的说法、查找来源并说明证据状态。批判性思考应检查前提、证据、推理及遗漏条件，也说明合理之处。梳理分歧应说明各方主张和共识，并辨别事实、定义与价值判断的分歧。

可根据本次概览提供具体的后续问题，例如针对概览中某个话题进一步提问。

## 个人倾向分析

本期个人分析仅使用历史主题、回复和必要前情中的文本，不加载或分析图片。

用户特别要求突出个人倾向。首次报告应优先归纳在所读取发言中反复表现出的兴趣与偏好、议题立场、判断侧重，以及这些表述的稳定性和变化。

判断需附代表性发言和时间，区分反复出现与偶尔表达的偏好；有相反表述时同时展示，并考虑引用他人、反讽以及讨论条件的区别。

政治、健康、性向、宗教、民族等敏感属性只整理本人明确表达的内容，不凭活跃版块或言论风格推断未公开的身份或归属。分析使用中立、具体的表达，并限制在所读取样本能支持的范围内。匿名作者不提供个人分析入口。

用户可以继续询问判断依据、其他主题中的表述和近期变化。

## 对话与历史

临时收起 AI 再展开，继续当前对话；重新从内容入口发起分析，按这次选中的内容生成概览。不能将所有重新进入都自动恢复成该入口最近一次旧对话。

AI 对话历史是正式功能，设独立入口。自动保存概览与后续聊天，记录标题、来源主题／楼层／用户和时间。历史记录支持继续聊天与删除，原内容附近可以找到相关对话。

同一个主题可以存在多条对话，保留各自当时的阅读范围。历史对话的旧回答保留原状，用户可继续询问后续进展。

沿用用户认可的默认方向：历史保存在本机、全账号共享，保留至用户删除；每条对话独立，续聊使用本条对话的历史，不自动引入其他对话或其他人的分析报告。历史不保存论坛原文快照，只保留引用坐标；帖子被论坛清理后引用预览显示不可访问。

## 展示与返回

从内容进入时先打开半屏面板，方便对照原内容；支持上拉至全屏。收起后保留本次对话及原阅读位置。从历史记录进入时直接打开完整聊天页面。

### 来源引用

论坛内容的引用点击后先预览原文，用户可进一步跳到对应主题或楼层。站外来源显示来源标题，点击打开原网页。查看来源后返回时保留原对话及聊天位置，用户可以继续追问。

## 已确认的运行行为

- 显示当前正在读取内容、联网查找资料或生成回答；生成回答时逐步显示已经产生的文字。
- 展示实际读取的主题／页码／楼层、图片数量；个人分析展示主题与回复的样本数量、时间跨度。来源不完整时说明缺失范围。
- 提供停止操作，停止当前读取与生成，保留已产生的内容并标记未完成。
- 失败时保留用户输入与已有回答，支持在同一对话重试。
- 收起面板时当前请求继续进行，再展开可看到进展；用户通过停止操作结束当前请求。
- 切到其他应用后进程被系统结束时，运行标记为已中断，下次打开可继续并说明原因；不使用前台服务。

## 当前确认状态

功能范围、默认上下文、联网、快捷操作扩展范围、个人分析、对话历史、半屏／全屏、图片限制、引用查看、非图片附件边界及运行行为已整体确认为一期需求。后续修改需区分需求变化与技术实现选择。

用户已确认开销和异常处理的产品原则：一次分析内所有模型调用、思考、图片、摘要和重试共享额度，发送前检查，达到额度后保留成果并由用户决定继续；提供可选每日额度和用量展示。结果不明的请求不自动重放，局部失败如实说明，停止和进程中断不自动恢复付费工作，保存失败不能虚报成功。细化方案见 [开销控制与异常处理](cost-and-recovery.md)。

剩余评审聚焦完整界面与内置 skills 的回答示例。金额、次数、超时和并发默认值通过样本与兼容性验证后提出，尚未确定；不再重复确认已有的功能范围和行为原则。框架接入已实现，界面、业务工具、持久化、预算与真实模型联调仍由后续票推进。

## 评审后补充确认

2026-09-13 用户逐条确认：

- 个人分析的主题条目首次只按标题计入；agent 判断需要时再用工具读主楼，受限速与预算约束，不默认全部补读。
- 匿名作者没有稳定 uid，个人分析入口对匿名作者不可用；主题与楼层分析中匿名作者以「匿名用户」表示，本地还原的六字假名不送入模型。
- 被本地屏蔽规则或官方屏蔽词隐藏的内容一律不进入上下文，工具读取时同样过滤；回答中说明有被屏蔽楼层未计入。
- AI 读图不受「仅 Wi-Fi 加载图片」设置限制，开销由预算控制。
- AI 对话历史全账号共享，与书签一致；引用预览用当前账号读取，无权限时显示「当前账号无法查看」。
- 主题详情与列表单条主题入口的首次概览默认带入热门回复，并在阅读范围中注明。
- 「不推断未公开身份」推广到健康、性向、宗教、民族等所有敏感属性：只整理本人明确表达，不凭版块或风格推断。
- 切到其他应用后进程被系统结束时，运行按「已中断」处理，下次打开可从检查点继续，界面说明原因；不加前台服务。
- 历史只永久保留对话、阅读范围和引用坐标（tid/pid），不保存论坛原文快照。论坛会定期清理帖子，引用预览每次重新读取，读不到时显示已删除或不可访问；agent 在续聊时被告知早先读到的内容可能已不存在，需要引用原句时重新读取。
