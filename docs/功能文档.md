# NGA 第三方客户端功能调研文档

> 调研对象：
> - **MNGA**（[BugenZhao/MNGA](https://github.com/BugenZhao/MNGA)）：iOS/iPadOS 客户端，SwiftUI 前端 + Rust 逻辑层 + Protobuf 通信。⚠️ NO LICENSE，代码不可修改/再分发，只能参考思路。
> - **NGA-CLIENT-VER-OPEN-SOURCE**（[Justwen/NGA-CLIENT-VER-OPEN-SOURCE](https://github.com/Justwen/NGA-CLIENT-VER-OPEN-SOURCE)）：Android 客户端，**现行权威版本 v4.2.2，活跃维护中（截至 2026-08）**，Java/Kotlin 混合 + 局部 Jetpack Compose，minSdk 30。ymback fork 是它的历史上游（停更于 2022-07 的 v3.7.6，手机截图对应此版本）。

> API 细节见同目录《API文档.md》；完整原始调研报告在 `docs/research/` 下（`nga-android-v4-delta-report.md` 记录 v3.7.6→v4.2.2 的全部差异及源码证据）。

## 1. 两个项目的整体架构

### 1.1 MNGA：三层结构（最值得借鉴）

```
SwiftUI (app/)  Views / DataSource / @AppStorage
      │  Protobuf 字节流 + C ABI（rust_call / rust_call_async）
Rust FFI 胶水层 (logic/logic)  tokio Runtime 单例，panic 全部 catch_unwind
      │  oneof 分发（9 个同步服务 + 29 个异步服务）
Rust 业务层 (logic/service)  fetch.rs(HTTP) + topic/post/forum/user/msg/noti/clock_in
      ├─ logic-text  : BBCode 解析（peg 语法）/ 提交转义
      ├─ logic-cache : sled 本地 KV 缓存（帖子缓存、通知已读、投票状态、浏览历史）
      └─ logic-config: 运行时配置
      │  HTTPS (reqwest)
NGA 服务器
```

**核心设计决策：BBCode 解析在 Rust 侧完成**，返回结构化的 `Span` 树，Swift 只负责把树映射成视图（`ContentCombiner.swift`，1020 行）。好处是换平台时渲染以外的逻辑全部可复用。契约定义在 `protos/DataModel.proto` + `protos/Service.proto`。

### 1.2 NGA-CLIENT：组件化多 module（v4.2.2 现状）

v4.x 完成了组件化改造，从 5 个模块拆成 13 个（完整表见 delta 报告 §A1），核心分层：

| 模块组 | 实际内容 |
|---|---|
| `nga_phone_base_3.0` | 主 App（帖子列表/详情、编辑器、设置等老 View 体系仍在此） |
| `lib_core` / `lib_core_data` | BBCode → HTML 渲染引擎（Decoder 链 + Builder 链 + HTML 模板 + 本地表情素材）/ 短消息 bean |
| `lib_base_network` | RetrofitHelper + RxJava2 版 RetrofitService + 协程版 RetrofitServiceKt |
| `lib_base_ui` / `lib_base_ui_compose` | Base Activity/Fragment；Compose 基建（BaseComposeActivity、下拉刷新 LazyColumn、theme） |
| `lib_base_common` / `lib_base_service_api` / `lib_base_logger` | 工具 + KV 存储 / ARouter 路由服务接口 / 日志 |
| `lib_bu_account` / `lib_bu_message` | 账号业务（WebView 登录 + Room 多账号）/ 短消息业务（全 Compose） |
| `lib_bu_statistics` / `lib_module_debug` | Bugly/友盟隔离层 / 调试模块 |

- **架构模式**：老页面 MVP（contract/model/presenter + Fragment），新页面 Compose + ViewModel + Repository（搜索、板块列表首页、抽屉、屏蔽管理、短消息、登录、用户管理已 Compose 化）；ARouter 1.5.2 做跨模块路由。
- **网络层三轨制**：Retrofit + OkHttp + RxJava2（老页面）；Retrofit suspend 协程 + Paging 3（Compose 页面，短消息用了分页）；裸 `HttpURLConnection`（`HttpPostClient`）处理需要 GBK 表单体的 POST（发帖、贴条、改头像、投票——短消息已迁走）。
- **数据解析**：无自动映射，全部 fastjson 手工遍历 + 正则清洗（NGA 返回的是非法 JSON）。fastjson2 已引入依赖但尚未实际使用。
- **内容渲染**：BBCode → HTML → WebView，**v4.x 也没换**。Decoder 链（基础标签 / 相册 / 表情 / 图片 / 评分帖 / 骰子）+ Builder 链（附件 / 贴条 / 签名 / 投票 / 尾部），套 `assets/html/html_template.html` 模板，夜间模式换 CSS。
- **版本基线**：minSdk 30（Android 11）、targetSdk 35、Kotlin 2.0.21、AGP 8.6.1、Compose 1.7.0。

#### v3.7.6 → v4.2.2 演进摘要（详见 delta 报告）

- **新增**：短消息整体重写（Compose + lite=js 接口，旧版被服务端拒的问题已解决）；板块列表在线更新（`app_api.php` 24h 节流增量合并）；版头（版面头条帖）；官方屏蔽词云同步（`ucp get/set_block_word`）；屏蔽关键词支持正则；自动签到（默认关）；被喷计数徽标；图片域名从 `read.php` 响应的 `_ATTACH_BASE_VIEW` 字段动态获取（修复了硬编码 `img.nga.178.com` 失效导致的碎图——手机截图里的图片挂掉就是这个）；Material You 图标；edge-to-edge。
- **移除**：账号密码登录（仅剩 WebView 抓 Cookie）；老短消息界面；全站版面在线浏览入口；侧滑返回。
- **重构**：抽屉、用户管理（SP JSON → Room）、登录、WebView 容器（兜底逻辑保留，实现更换并修掉循环重试/多次返回问题）。

### 1.3 两种渲染路线对比（复刻时的关键选型）

| | MNGA | NGA-CLIENT |
|---|---|---|
| 路线 | BBCode → Span 树 → 原生视图 | BBCode → HTML → WebView |
| 优点 | 原生滚动/手势/选择体验，性能好 | 实现快，CSS 换肤容易，表格等复杂排版免费 |
| 缺点 | 每个标签都要写原生渲染，工作量大 | WebView 内存重，与原生 UI 交互要走 JS Bridge |
| 投票功能 | 未实现原生投票渲染 | WebView + `vote.js` + `@JavascriptInterface` 桥接 |

### 2.9 内容渲染支持的 BBCode 标签

两边并集（复刻时的目标清单）：

- **文字样式**：`[b] [i] [u] [del] [color=](26色) [size=%] [font]`（MNGA 忽略 font）
- **结构**：`[quote] [code] [collapse(=标题)] [list]/[*] [table]/[tr]/[td colspan/rowspan] [align=] [l] [r] [h] ===标题=== / ======（分割线）`
- **链接/引用**：`[url] [uid] [tid] [pid] [@用户名]`（`[pid=a,b,c]` 指向 `read.php?searchpost=1&pid=a`）
- **媒体**：`[img] [noimg] [album] [attach] [flash] [flash=video] [flash=audio]`
- **表情**：`[s:分类:名称]`，6 套素材（ac/a2/pst/dt/pg/xiongmao），应内置本地，远程 URL 命中时反查换本地
- **特殊**：`[dice XdY]`（**客户端本地复刻 NGA 伪随机**：种子=authorId+tid+pid，`(seed*9301+49297)%233280`）、`[lessernuke] [hip] [item] [stripbr]`
- 未知标签原样透传显示

图片额外处理：`[img]./xxx` 相对路径拼附件域名——**域名优先从 `read.php` 响应的 `__GLOBAL._ATTACH_BASE_VIEW` 字段动态获取**（NGA-CLIENT v4.2.2 做法，硬编码域名仅兜底；MNGA 硬编码 `img.nga.cn`）；剥缩略图后缀 `.thumb_s/.medium/.thumb`；`[noimg]` 需按发帖日期拼 `mon_YYYYMM/DD/` 前缀。

## 3. 对复刻项目的建议

1. **架构上学 MNGA，实现节奏上学 NGA-CLIENT**：把「API 请求 + 响应清洗 + BBCode 解析」做成与 UI 无关的核心层（不必是 Rust，同语言的独立 module 即可），UI 层只消费结构化数据。渲染想快先用 HTML+WebView（NGA-CLIENT 的 lib_core 管线可以整体照抄思路），后期再换原生。
2. **最大的工作量不在 UI**，在三件事：编码处理（GBK/UTF-8 混杂）、响应清洗（非法 JSON/前缀剥离）、BBCode 渲染。详见 API 文档的"复刻要点"。
3. **反封锁必须一开始就设计进去**：NGA 会封第三方客户端的 XML/JSON 接口。MNGA 的四层兜底（换格式参数 → Web HTML 反解 → 反向代理 → 本地缓存）是它最核心的竞争力。
4. **纯本地实现的功能清单**（不用等 API 就能做）：热门话题聚合、匿名用户名还原、骰子结果计算、通知已读、浏览历史、黑名单/关键词过滤、彩色标题解码。
5. **跟进 Justwen fork 的活跃维护**：它是唯一还在适配 NGA 服务端变化的开源客户端（例：2024 年 `parent` 字段变字符串化 JSON 的兼容、2026 年图片域名下发），复刻项目遇到接口解析问题时先去看它的最新提交，大概率已有现成答案。
6. MNGA 的 `AGENTS.md` 提到的第三方接口文档可交叉验证：
   - https://github.com/wolfcon/NGA-API-Documents/wiki
   - https://gitee.com/AgMonk/nga-api-doc
