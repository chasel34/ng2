# ADR-0005：Room 维护正式迁移，升级不丢用户数据

状态：采用；2026-09-13。

## 决定

`ng2n.db` 从「结构变更即破坏性重建」改为整库维护正式迁移：

- 去掉 `fallbackToDestructiveMigration`，每次提高数据库版本都必须附带迁移（纯加表/加列用 `autoMigrations`），并把新版本的 schema JSON 提交进版本库。
- 缺迁移或版本倒退时应用启动即崩溃：`StorageBootstrap.open` 在启动预热里主动打开数据库，不吞 Room 的异常。
- 不开「降级时清库」，降级安装需要手动清应用数据。
- 表按可否重建分两类：`bookmark` 由用户创建、无法重建，迁移必须保数据；`browse_history`、`topic_cache`、`notification_read` 可重建，迁移允许删表重建。

## 理由

书签是用户手工写下的备注和位置，丢了没有任何来源能补回来。之前三张表都能从服务端或浏览行为重建，静默清库的代价可以接受；加入书签后不再成立。破坏性回退的另一个问题是错误被藏起来：漏写迁移时用户看到的是数据消失，而不是一个能在开发期就发现的崩溃。

## 后果

- 迁移测试进入设备测试（`room-testing` 仅用于 `androidTest`），改结构的提交要跑 `:app:connectedDebugAndroidTest`。
- 装过新版本的设备装回旧版本会崩溃，开发机切分支时需要手动清数据。
- 任何升级版本号却漏写迁移的改动会在启动时暴露，代码评审要把关。
